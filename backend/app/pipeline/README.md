# Pipeline

Фоновая обработка лекций в arq-воркере: скачивание или извлечение аудио, пережатие видео, распознавание, конспект, эмбеддинги. Шаги и их прогресс хранятся в `processing_steps`.

## Статус для фронта

`GET /api/v1/lectures/{id}/status` отдаёт статус лекции, место в очереди и список шагов. Ответ лёгкий, его можно опрашивать раз в 2 секунды.

## События

При смене статуса лекции воркер публикует JSON в Redis-канал `lecture-events`:

```json
{
  "lecture_id": "6f1c2a7e-3b4d-4e5f-8a9b-0c1d2e3f4a5b",
  "user_id": "0a1b2c3d-4e5f-6a7b-8c9d-0e1f2a3b4c5d",
  "status": "failed",
  "error": "Не хватает лимита на обработку лекции"
}
```

| Поле | Тип | Что там |
|---|---|---|
| `lecture_id` | UUID строкой | лекция |
| `user_id` | UUID строкой | владелец лекции |
| `status` | строка | `processing`, `ready` или `failed` |
| `error` | строка или `null` | текст ошибки шага, заполнен только для `failed` |

Событие отправляется после коммита в базу, так что по `lecture_id` можно сразу запросить свежие данные. Если Redis недоступен, событие теряется, обработка продолжается.

## Памятка к экзамену

`POST /api/v1/courses/{id}/exam-sheet` ставит в очередь сборку памятки по конспектам лекций курса и отвечает `202`. Доступно только с подпиской. Если в курсе нет лекций с готовым конспектом, ответ `409` с `detail.code = no_summaries`. Если очередь недоступна, оба эндпоинта отвечают `503`.

Воркер сначала просит LLM вытащить из конспекта каждой лекции билеты, определения и шпаргалку, потом сводит всё в одну памятку. Новая памятка заменяет старую, пока новая не готова, отдаётся старая.

`GET /api/v1/courses/{id}/exam-sheet` отдаёт `ExamSheetOut`. Пока памятки нет, ответ `404`, `detail.code` показывает причину:

| `detail.code` | Что значит |
|---|---|
| `exam_sheet_processing` | памятка в очереди или собирается, можно опрашивать дальше |
| `exam_sheet_not_found` | памятку не запускали или сборка не удалась |
