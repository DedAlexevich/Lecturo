# Логи

Каждый сервис пишет логи в файл `data/logs/<сервис>.log` (папка внутри `DATA_DIR`, см. [data.md](data.md)) и продолжает выводить их в stdout, поэтому `docker compose logs` работает как раньше. Исключение: access-лог Caddy пишется только в файл. Файлы переживают пересоздание контейнеров и `docker compose down -v`.

| Файл | Сервис | Что внутри |
|---|---|---|
| `api.log` | `api` | запросы uvicorn, ошибки приложения, письма в режиме лога (при пустом `SMTP_HOST` там же ссылки подтверждения и сброса пароля), ошибки yt-dlp при проверке ссылки |
| `worker.log` | `worker` | задачи arq, ошибки шагов обработки лекций (с трейсбеками), ошибки ffmpeg и yt-dlp |
| `bot.log` | `bot` | работа Telegram-бота |
| `caddy.log` | `caddy` | служебные сообщения и access-лог прокси |
| `tusd.log` | `tusd` | запросы и ошибки загрузки файлов |
| `mail.log` | `mail` (только на сервере) | приём и доставка писем Postfix, подпись OpenDKIM |

Формат строк у `api`, `worker` и `bot`: время, уровень, сервис, логгер и сообщение.

```
2026-10-27 13:10:54,692 INFO api app.services.mail: Письмо для a@example.org: ...
```

`caddy`, `tusd` и `mail` пишут в собственных форматах.

## Ротация

Файлы `api`, `worker`, `bot`, `tusd` и `mail` ротируются по правилу: когда файл достигает `LOG_MAX_MB` мегабайт (по умолчанию 10), он переименовывается в `<сервис>.log.1`, прежние копии сдвигаются, а самая старая сверх `LOG_BACKUP_COUNT` (по умолчанию 5) удаляется. Для `api`, `worker` и `bot` это делает `RotatingFileHandler`, для `tusd` и `mail` скрипт `infra/log-to-file.sh`. Скрипт считает размер приблизительно и сверяет его с реальным через `wc -c` раз в 100 строк, поэтому файл может немного превысить лимит.

`caddy` ротирует сам (`roll_size`, `roll_keep`, `roll_uncompressed` в `infra/Caddyfile`): архивы называются `caddy-<время>.log` и не сжимаются. Файлы `caddy.log.1` ... `caddy.log.5` от прежней обёртки на сервере сами не удалятся, их можно удалить вручную.

На каждый сервис уходит порядка `LOG_MAX_MB * (LOG_BACKUP_COUNT + 1)` МБ.

Запасной вариант: json-логи Docker для всех сервисов ограничены `max-size: 10m` и `max-file: 3`.

## Как смотреть

```
tail -f data/logs/api.log
grep ERROR data/logs/worker.log*
docker compose logs -f api worker
```

Файлы создаются от имени root внутри контейнеров. Логи Caddy, tusd и mail, включая ротации, имеют права `640`: читать их могут root и участники группы-владельца; остальным нужен `sudo`. Изменять и удалять логи нельзя.

После первого деплоя фильтра секретов очистите прежние файлы Caddy: в них могут остаться значения токенов, записанные до обновления. На сервере укажите фактический каталог логов вместо `/path/to/data/logs`:

```
sudo find /path/to/data/logs -maxdepth 1 -type f \( -name 'caddy.log*' -o -name 'caddy-*.log' \) -exec truncate -s 0 -- {} +
caddy_container=$(docker compose ps -q caddy)
caddy_docker_log=$(docker inspect --format='{{.LogPath}}' "$caddy_container")
sudo truncate -s 0 "$caddy_docker_log"
```

## Как это устроено

Для `api`, `worker` и `bot` путь и имя файла задают переменные `LOG_DIR` и `LOG_SERVICE` из `docker-compose.yml`. Без `LOG_DIR` (например, при запуске тестов или `uvicorn` на хосте) логи идут только в stdout. Caddy пишет файл сам: путь, размер и число копий заданы в блоках `log` файла `infra/Caddyfile` (размер и число копий берутся из `LOG_MAX_MB` и `LOG_BACKUP_COUNT`). Для `tusd` и `mail` точка входа заменена на `infra/log-to-file.sh`: скрипт запускает сервис, копирует его вывод и в stdout, и в файл, держит файл открытым и ротирует его по размеру в байтах.

Access- и runtime/error-логи Caddy во всех каналах удаляют query-параметры `token`, `signature` и `share`, а заголовок `Referer` не записывают: в нём может находиться ссылка сброса пароля или подтверждения почты. Фильтры настроены отдельно для файла, stdout и access-лога.

## Чтение из админ-панели

Раздел «Логи» в `/admin` читает `api.log`, `worker.log`, `bot.log`, `caddy.log` и `tusd.log` из `LOG_DIR` (внутри `api` это `/var/log/lecturo`, тот же том, что у остальных сервисов). Имя файла берётся только из списка сервисов, символические ссылки не открываются. Токены, пароли, ключи, ссылки с `?token=` и подобными параметрами маскируются, почта показывается частично (`i***@e***.org`). Поток в реальном времени держит не больше `LOG_STREAM_LIMIT` соединений.
