# Хранение данных

База, загруженные файлы и служебные данные лежат в папке на хосте, а не в томах Docker. Папка задаётся переменной `DATA_DIR` (по умолчанию `./data` в корне репозитория), в git она не попадает. `docker compose down -v`, сброс Docker и переустановка WSL данные не затрагивают.

| Папка | Что внутри | Кто пишет |
|---|---|---|
| `data/postgres` | данные Postgres: пользователи, лекции, конспекты | `db` |
| `data/storage` | загрузки, оригиналы, аудио и видео лекций | `api`, `worker`, `tusd`, читает `caddy` |
| `data/bot-redis` | очередь уведомлений бота (Redis с AOF) | `bot-redis` |
| `data/zoomer` | вертикальные ролики режима зумера (`.mp4`, `.webm`), отдаются по `/zoomer/` | владелец вручную, читает `caddy` |
| `data/caddy` | сертификаты и состояние Caddy | `caddy` |
| `data/mail/dkim` | ключ DKIM для подписи писем, только на сервере | `mail` |

## Запуск

Ничего создавать вручную не нужно: на чистом клоне хватает `cp .env.example .env` и `docker compose up --build`. Docker сам создаёт недостающие папки, а контейнеры при старте выставляют права на свои данные (Postgres и Redis делают `chown` своей папки, остальные сервисы работают от root).

Папки внутри `data/` принадлежат пользователям контейнеров (`postgres` с uid 999, root), поэтому с хоста их содержимое без `sudo` не удалить и не изменить. Чтобы очистить данные целиком, остановите проект и выполните `sudo rm -rf data`.

Чтобы хранить данные в другом месте, задайте `DATA_DIR` в `.env`, например `DATA_DIR=/srv/lecturo`. Путь может быть абсолютным или относительным к корню репозитория.

## Postgres и файловая система

Postgres нужны права владельца и режим `0700` на папку данных. Это работает на ext4, то есть внутри файловой системы WSL (`/home/<user>/...`) и на Linux-сервере. На смонтированных дисках Windows (`/mnt/c/...`) права не применяются, и Postgres может не стартовать с ошибкой `data directory has wrong ownership` или `could not change permissions`. Клонируйте репозиторий и держите `DATA_DIR` внутри WSL, а не в `/mnt/c`.

## Перенос из старых томов

Раньше данные хранились в именованных томах `lecturo_pgdata`, `lecturo_storage`, `lecturo_botredisdata` и `lecturo_caddy_data`. Чтобы забрать их в папку на хосте:

1. Обновите код и остановите проект: `docker compose down` (без `-v`).
2. Запустите `./scripts/migrate-volumes.sh`.
3. Поднимите проект: `docker compose up -d --build`.
4. Проверьте, что пользователи и лекции на месте.
5. Старые тома остаются нетронутыми, удалить их можно позже: `docker volume rm lecturo_pgdata lecturo_storage lecturo_botredisdata lecturo_caddy_data`.

Скрипт копирует каждый том через временный контейнер `alpine` с сохранением прав и владельцев, затем сравнивает число файлов и общий размер тома и папки. Он ничего не удаляет и не перезаписывает: если том не найден, пропускает его, а если целевая папка не пуста, останавливается с ошибкой (например, после случайного `up` до переноса там лежит пустая свежая база: уберите её и запустите скрипт снова). Если том используется запущенным контейнером, скрипт останавливается с ошибкой: пока Postgres работает, копировать его данные нельзя.

Переменные скрипта:

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `DATA_DIR` | Папка назначения | значение из `.env`, иначе `./data` |
| `COMPOSE_PROJECT_NAME` | Префикс имён томов; задайте, если проект запускался из папки с другим именем | `lecturo` |
| `MIGRATE_IMAGE` | Образ временного контейнера | `alpine:3` |
